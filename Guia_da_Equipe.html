O repositório

Todo o trabalho fica num repositório no GitHub: gussimonn/lumis-fiap-grupo2. Pense nele como uma pasta compartilhada que guarda o histórico de cada alteração, com quem mudou o quê e quando. Cada um tem uma cópia no próprio computador e sincroniza com o GitHub.

Sincronize antes de começar. Sempre.

Antes de abrir, ler ou editar qualquer arquivo, puxe o que a equipe mudou. No Claude, a primeira mensagem do dia é atualiza a pasta com o GitHub. Quem trabalha numa versão velha sobrescreve o trabalho dos outros, e no .docx isso não tem conserto.

O ciclo de trabalho

ClonarUma vez só: baixa a pasta inteira para o seu computador.
Atualizar (pull)Toda vez, antes de qualquer trabalho. Sem exceção.
Salvar (commit)Registra o que você fez, com uma frase dizendo o quê.
Enviar (push)Manda o seu commit para o GitHub e a equipe passa a ver.

Duas formas de usar

Claude Desktop

Para quem não quer mexer com terminal. Abra a pasta do repositório no Claude Desktop e peça em português: primeiro "atualiza a pasta com o GitHub", depois "o que falta na Fase 2?", "salva e envia o que eu fiz".

O Claude lê o CLAUDE.md da pasta e já segue as regras do projeto: onde gravar, como citar a fonte, qual padrão visual usar.

IDE (VS Code, Cursor…)

Para quem quer ver os arquivos lado a lado. O painel de controle de versão da IDE mostra o que mudou e tem botões para pull, commit e push. Comece sempre pelo pull.

Com a extensão do Claude Code instalada, o Claude roda dentro da IDE com as mesmas regras do CLAUDE.md.

Cuidado com o Word

  • O Git não junta duas edições do mesmo .docx. Se duas pessoas mexerem no mesmo arquivo ao mesmo tempo, uma das versões se perde. Combine no grupo quem está editando cada entrega.
  • Feche o Word antes de salvar e enviar. Arquivos que começam com ~$ são temporários do Word e não devem ir para o repositório.

O que dissemos vira régua

Os cinco compromissos da Declaração de Intenção (F1-E3) vão ser usados para julgar nossas decisões nas próximas fases. Toda entrega nova é conferida contra eles.

Contradição custa caro

Na Fase 7 defendemos tudo diante de investidores, regulador e sociedade civil. Se a F2 diz uma coisa e a F5 diz outra sem explicar, perdemos credibilidade.

Só o que está no capítulo

Número da Lumis só vale se estiver no enunciado. O que não está é "não consta", e conclusão sem quadro que a sustente é marcada como hipótese.

Para começar uma entrega

  • Copie Modelo_Entrega_Lumis.docx para a pasta da entrega com o nome padrão (ex.: F2-E2_Auditoria_do_Ativo_v1.docx).
  • Troque capa e cabeçalho e escreva usando só os estilos da galeria do Word. Nada de cor ou fonte aplicada à mão.
  • Logo e Feixe (a arte da capa) vêm prontos em 00_Lumis/Design_System/. O Feixe aparece uma vez por documento, na capa.

Combinados

  • Sincronize antes de qualquer trabalho e envie assim que terminar.
  • Antes de perguntar "onde estamos?", abra o ESTADO.md.
  • Decisão tomada vira entrada no DECISOES.md. Lá só se acrescenta, nunca se apaga.
  • Antes de substituir uma versão, a anterior vai para _Historico/.
  • Uma entrega tem um único arquivo vigente, em .docx.
  • Nomes de arquivo e pasta sem acento. O conteúdo é escrito em português normal.
  • Lumis Intelligence é a empresa. Lumis Insight é o produto.
  • Os PDFs do curso têm marca d'água com dados pessoais. Esses dados não entram nos arquivos de trabalho.
